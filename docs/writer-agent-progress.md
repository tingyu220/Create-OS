# Writer 运行进度与等待操作体验

状态：已完成，2026-10-18。保持当前分支和所有原有未提交修改；未 commit、push 或合并，未重启 8877 服务。

## 设计与范围

面向等待分析或候选生成的作者。沿用现有三栏、绿色强调色和紧凑密度，在 Agent 固定头部展示阶段、用时、最近状态更新时间及只读“查看状态”。详细任务历史独立滚动；手机保留输入、发送按钮和禁用原因。参考现有 Writer 组件与 designing-frontend-ui 的状态、可访问性及视觉核验规范，无新增依赖或外部视觉素材。

实施顺序：隔离时间与竞态测试 → Runtime 时间持久化 → 独立展示计时 → 只读状态查询及禁用原因 → Fake 模型浏览器验收。

## 数据与行为

- `AgentJob.started_at`：任务受理排队时记录，整个任务不再修改；每次显式重试创建新任务并取得自己的开始时间。
- `AgentJob.status_updated_at`：仅状态、状态说明或错误实际变化时更新；`updated_at` 继续表示任务记录更新时间。会话查询和本地计时不更新这些字段。
- 旧快照字段默认空字符串，不把页面打开时间或最后更新时间当作开始时间。前端明确提示旧任务缺少时间；有更新时间时作为“最近任务记录”展示。
- 当前任务每秒用持久开始时间计算用时，刷新不归零；完成或失败后使用终止记录时间固定总用时。阶段“分析本章”和“生成候选”区分显示。
- 阶段超过 60 秒未变化时，thinking 提示仍等待模型服务响应，其他阶段提示等待当前阶段更新。不提供百分比、token 流或预计完成时间。
- 查询失败保留最后任务状态和计时，明确尚未确认完成或失败；只重新查询，不重新执行。新增手动查看状态沿用现有会话 Query，并以请求代次隔离同章迟到查询。
- 运行期间禁用新任务和审阅操作，通过可见中文说明、按钮 title 和 aria-describedby 解释原因；候选尚无正文时解释阅读按钮不可用的原因。已有候选、来源和补充输入仍可使用。
- 提交未返回时，手动查询不能提前解禁新任务；前端请求入口同时防止忙碌时重复提交。
- 页面恢复时仅将已完成历史任务标记为已处理。恢复中的任务后续完成仍会解禁并打开新候选；不自动打开恢复前已完成的历史候选或工作稿。
- 当前没有可靠运行取消能力，明确“暂不支持中断”；原有“取消提案”仍只是候选审阅行为。没有新增运行取消按钮或另一套任务系统。
