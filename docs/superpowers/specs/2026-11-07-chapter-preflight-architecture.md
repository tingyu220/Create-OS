# 章节前置架构分析规格

## 目标

在每次正文生成前，读取冻结的前文、项目设定、历史状态和未解决问题，形成一份章节架构计划。战斗编排只是按需启用的子分析，不是每章必经步骤。

## 流程

`queued → reading_context → classifying → composing → analysis_ready → writing → editing → accepted`

任何阶段都支持 `paused`、`failed` 和可审计的继续；继续必须复用原分析版本和来源哈希。

## 分析结果

章节计划至少包含：

- 主线目标与本章结果；
- 场景类型和场景顺序；
- 势力、人物或场景之间的冲突；
- 需要回收的伏笔；
- 需要埋下的新伏笔；
- 人物、资源、地点、时间和事件状态变化；
- 结尾悬念；
- 未知项与证据引用；
- `combat_plan`，仅在确有战斗或行动链需求时存在。

## 子分析

协调器按需调用剧情推进、伏笔、冲突、战斗、连续性和节奏分析。普通对话、过渡、调查或情感章节可以不调用战斗子分析。证据不足时保留未知，不用关键词命中替代判断。

## 写作与编辑

Writer 只能消费 `analysis_ready` 的冻结计划，不得自行替换前置计划。编辑对照计划检查主线、伏笔、冲突、状态变化和结尾悬念，生成验收结果；修订仍绑定同一计划版本。
