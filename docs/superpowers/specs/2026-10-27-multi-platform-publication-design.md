# 多平台自动发布设计（番茄首个适配器）

## 目标

将项目中的正式稿章节按顺序自动发布到用户已打开的番茄作品。流程包含自动写作、自动检查、浏览器填充、发布、结果核对和证据记录；支持全局、单书、单章及当前步骤的暂停与继续。其他平台通过适配器扩展，第一版不实际接入。

## 范围与边界

- 只操作用户已经创建并在浏览器中打开的番茄作品，不自动创建作品、登录账号或保存密码。
- 不绕过验证码、风控或平台访问限制。
- 不触碰真实账号进行首次发布验证；实现与验收使用临时项目、Fake 浏览器和隔离端口。
- 正式发布不再逐章等待人工审批，但保留总开关、暂停、继续、重试和状态未知锁。

## 组件

### PublicationOrchestrator

按章节协调正式稿选择、自动检查、平台填充、发布和核对。每次动作使用任务快照和幂等操作标识。

### PlatformAdapter

统一平台边界，首个实现 `TomatoBrowserAdapter`。接口包括 `connect`、`verify_target`、`prepare_chapter`、`fill_chapter`、`publish`、`query_result`、`capture_evidence`。平台差异不能泄漏到写作、检查和队列模块。

### PublicationQueue

按作品和章节顺序排队，限制同一作品并发，允许不同作品独立运行。已发布章节不可自动重发。

### CheckpointStore 与 PublicationLedger

检查点保存书、章节、正式稿版本、当前步骤、操作标识和正文哈希。发布台账保存平台章节号、发布时间、结果状态、页面证据和哈希。状态未知与失败严格分开。

### RunControl

提供安全暂停、立即暂停和继续。安全暂停等待当前动作到安全边界；立即暂停中断当前动作。发布动作被立即中断或响应丢失时必须进入状态未知，继续前先查询页面，不能直接重发。

## 自动检查门槛

只有全部门槛通过才允许填充和发布：正式稿版本连续、章节标题和字数正确、人物和设定一致、战斗/冲突场景检查通过、敏感内容和格式检查通过、平台作品与章节匹配、章节未发布且正文哈希未变化。

## 状态机

```text
写作中 → 检查中 → 待填充 → 填充中 → 待发布 → 发布中 → 核对中 → 已发布
                         ↘ 失败
任意状态 → 安全暂停 → 已暂停 → 恢复中 → 原状态
任意可中断状态 → 立即暂停 → 已暂停或状态未知
```

状态未知必须先核对平台结果；失败可按策略重试；已发布、状态未知和版本冲突不得静默重发。

## 数据流与安全

任务只引用正式稿快照，不直接读取可变工作稿。每次平台动作带 `operation_id`、目标书/章标识、版本和正文哈希。跨书、跨章或版本不匹配时暂停。浏览器会话只使用用户已登录的现有会话，不落盘凭据。

## 验收

第一阶段使用两个临时项目和 Fake 浏览器验证：顺序逐章发布、自动检查阻断、普通写作兼容、跨书隔离、重复发布保护、失败/验证码/登录失效、发布中丢响应、两种暂停、继续恢复、状态未知核对、1440/390 布局和键盘可操作性。不得调用真实模型、真实番茄账号、生产 Runtime 或 8877。

## 后续平台

新增平台只实现 `PlatformAdapter`，并声明其支持能力；不假设所有平台均支持创建作品、定时发布或结果查询。缺失能力必须显式显示为人工步骤或不可用。

## 持久化浏览器工作台（第一版正式架构）

浏览器不再按章节临时启动。工作台维护一个长期存在的平台浏览器会话，在右侧固定显示番茄页面；用户首次手动登录，系统只复用现有会话，不保存密码。发布编排器通过会话控制器操作当前标签页，并持续展示平台、作品、章节、步骤、登录状态和操作状态。

会话控制器保存浏览器进程标识、页面标签标识、目标作品、当前步骤、operation_id 和正文哈希。暂停保留页面与输入内容；继续从页面状态和检查点恢复。浏览器崩溃、页面关闭、登录失效或验证码会进入 `browser_session_interrupted`/`paused`，重新连接后先核对页面和正文，再恢复，不直接重发。

其他平台使用独立标签页或独立持久化会话，不能共享登录状态或作品上下文。任务6验收必须覆盖窗口留在工作台、断开重连、暂停继续、验证码停留和跨平台隔离。
