# 工作台内嵌发布浏览器设计

## 目标

在 Creative OS 工作台右侧显示真实番茄作者后台，并让发布编排器通过同一持久化浏览器会话逐章完成填充、发布和结果核对。

## 现状与约束

- 当前 Writer 是普通 HTTP 页面，不能把番茄页面放进 iframe；番茄响应包含 `X-Frame-Options: SAMEORIGIN`。
- 不能复制 Cookie、密码或绕过验证码。
- 必须复用用户手动登录的持久化浏览器上下文。
- 当前验证只使用临时项目和 Fake/隔离浏览器，不触碰真实作品。

## 方案

采用桌面壳承载现有 Writer 页面和 WebView2 浏览器视图：左侧加载 `http://127.0.0.1:8899`，右侧加载番茄页面；两者通过本地受限桥接交换会话状态、作品/章节标识、正文哈希和发布结果。普通 HTTP 页面继续保留，便于测试和无桌面环境使用。

不采用 iframe 代理：无法携带真实登录态，且违反平台的跨站嵌入策略；不采用复制 Cookie：不安全且无法稳定工作。

## 桥接边界

- `BrowserHost`: 创建/恢复 WebView2 用户数据目录和标签页。
- `BrowserProbe`: 只读取当前 URL、登录提示、作品/章节标识和页面状态。
- `BrowserActions`: 在明确的发布步骤执行填充、保存、发布和结果读取。
- `PublicationOrchestrator`: 只接收适配器结果，不直接操作 DOM。
- 密码、Cookie、令牌不进入项目文件和 HTTP API。

## 验收顺序

1. 临时 WebView2 壳能同时显示 Writer 与 Fake 番茄页面。
2. 关闭并重启壳后会话可恢复，状态未知时必须先核对。
3. 临时作品逐章填充、发布、核对和暂停/继续通过。
4. 1440/390 布局及跨书隔离通过。
5. 最后才安排人工测试账号验证真实页面字段；不自动发布真实章节。
