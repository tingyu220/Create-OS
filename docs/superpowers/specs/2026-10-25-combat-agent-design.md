# 战斗编排专家 V1 设计

日期：2026-10-25。状态：设计草案，待作者批准；不授权实现、真实模型调用或正文修改。

## 意图及已确认范围

作者选择“主 Agent 按需调用战斗专家”，而非独立战斗工作台。以《文明升阶》为只读首个研究案例，同时提出后续冲突方向与前文伏笔补充清单；能力应可用于下一本小说。战斗是必备创作能力，不是每章必须执行的步骤。

目标是让科技、人物选择和对抗产生具体情节与代价。不能假定增加战争一定提高可读性，也不能凭作者提及其他国家或文明，就把敌对关系写成已确认事实。

## 方案比较

1. **已选：主 Agent 调用独立专家能力。** 保持一个对话入口、运行系统和作者决策边界；需明确专家输入及建议的身份。
2. 独立战斗工作台：方便集中管理，但增加页面、会话和上下文同步；首版不采用。

不采用固定战斗模板或数值模拟引擎：它们不能替代人物动机与叙事判断。

## 现有能力与接入原则

- ScenePlan/SceneContract 已有目标、冲突、行动、视角及状态变化；TechnologyContract 已有来源、前置条件、验证阶段和代价。
- NovelChapterPlanner 当前主要校验场景及章节边界，不能将它误称为已有自主战斗规划。
- WriterAgentRuntime、RuntimeRunner、实际模型消息捕获、故事设定冻结、Proposal 和作者反馈机制继续复用。
- Story 专家已有受控工具多轮推理入口；章节入口当前并非同样的工具循环。实现计划必须显式补齐主 Agent 的有限工具调用能力，不得用关键词匹配或隐式额外调用冒充自主委派。
- 专家推理放独立小模块，不继续扩张 Runtime 的大方法；不新建客户端、队列、Writer、事实库或通用代理框架。

## 使用方式

作者在现有对话提出“检查这段战斗”“规划下一场交锋”或“科技始终没有实际用武之地”。主 Agent 根据任务决定是否调用专家，也可直接回答或请求补充。作者明确要求专家时应调用，材料不足则说明缺口，不虚构已读材料。

专家可以受控读取本书已确认设定、正文及其来源片段，提出方案、比较方案或返回“不宜战斗”的理由。工具调用按需进行，不要求固定顺序。所有读取受项目、任务和预算限制，不能访问其他小说或任意路径。

主 Agent 将专家建议作为建议材料整合回复，不将结果自动写入正文或设定。用户可继续讨论、修改或拒绝。确认方案与接受生成正文是两个不同决定。

## 输入、输出与事实边界

输入必须绑定项目ID、会话、任务、目标章节/研究范围、用户意图、冻结的设定版本及来源清单。章节任务应包含目标章当前工作稿或正式稿，并标明选择依据；不得只读取邻章就断言目标章的问题。

专家输出包含：

- 本次判断：适合战斗、先铺垫、非战斗冲突更合适或证据不足，以及简短理由；
- 证据：实际读到的来源及版本/哈希，未读范围和未知项；
- 一个或多个可讨论方案：双方目标与信息差、可用能力及限制、空间/视角、关键行动与反制、选择与转折、胜负条件、代价及后续影响；
- 伏笔建议：需补什么、为什么、相关已读章节及依据、是否与现有事实冲突；不生成已经发生的历史；
- 未决问题与作者需确认的创作选择。

身份、来源和状态是严格结构；编排内容保持自由文本和可扩展段落，不强制每场使用同一套情绪或转折。战术内容服务虚构叙事，不输出现实武器制造或可直接实施的伤害指导。

## 确认与章节写作

**本设计的提议：** 将战斗方案作为现有故事候选内容中的有标识章节/片段，经现有候选编辑和明确确认机制形成不可变确认版本；不增设第二套审批存储。

主 Agent 不拥有确认权限。普通聊天“可以”不绕过明确确认。确认记录必须可追溯到专家结果、来源及适用章节；未确认方案不混入正式设定上下文。已确认未来计划仍标作“创作计划”，不是已发生事实，也不是必须逐句执行的模板。

章节请求受理时冻结适用的确认内容，实际进入写作模型消息并可查看来源；运行期间改计划不能偷换当前输入。超预算或缺必要来源须明确失败/请求缩小范围，不能悄悄截断并声称完整使用。正文生成沿用独立Proposal、冻结差异及作者接受；不自动发布。

既有旧项目无正式故事设定时，可先分析和提出候选；首版的“采用战斗方案写作”需明确确认候选后才启用，不改变普通旧章节写作兼容路径。不得用新增方案覆盖已有世界观或整个故事候选，编辑须绑定当前版本并检测冲突。

## 《文明升阶》首次研究

只读整理已写科技的实际能力与限制、现有阵营关系、冲突伏笔和未兑现的技术用途。必须区分正文证据、旧规划与本轮推测。

交付两份关联建议：后续冲突候选，以及前文最小伏笔补充清单。每条建议注明需要改动的范围和依据。未完整阅读全书时，不宣称全书没有战斗或没有伏笔。不能擅定某国或某文明为敌人，也不把技术研发直接等同成熟武器。

本次设计和自动化测试不运行真实付费模型，不写真实书。实际小说内容研究可只读；真实生成与改稿另按作者明确授权执行。

## 跨书复用

复用专家能力与编排方法，不复用《文明升阶》的角色、科技、阵营或情节作为下一本的事实。作者反馈沿用现有Feedback→经验候选→确认链；首版经验仍按作品隔离，不自动跨书检索。跨书迁移经验需后续显式导出/选择设计，不在首版扩展。

## 运行、错误与可观察性

同一运行系统内有界执行，记录专家调用及实际入模来源；显示简短创作依据，不暴露隐藏推理。步数、读取量和输出预算由实现者按现有约束确定并配置，耗尽可明确结束或继续，禁止无限递归委派。

取消、重试、并发改设定、跨项目请求及非法工具不得写入确认内容。重试沿用冻结输入与身份规则；失效结果不能覆盖新候选。复用现有锁、幂等、反馈及恢复语义。

## 验收条件

1. Fake 模型展示至少两种不同工具行动顺序；可选择非战斗或证据不足，不要求每章调用专家。
2. 作者明确调用、主 Agent 自主委派和普通不调用三条路径均有测试；专家不能确认或发布。
3. 两本临时小说使用不同设定，专家来源与生成内容严格隔离。
4. 未确认候选不入正式写作；确认后实际消息含正确内容/版本/哈希；运行中更新不污染冻结输入。
5. 目标章真实正文进入分析，缺正文不会编造章内缺陷；未读来源不可标为已读。
6. 临时浏览器完成讨论→专家建议→编辑候选→明确确认→章节候选→差异→接受工作稿；拒绝不改正文，重复确认/接受不重复版本。
7. 超预算、非法工具、冲突版本、失败重试及跨项目请求受控；全部验证仅临时项目/Fake，无真实模型或小说写入。

## 非目标及待批准决策

不做独立工作台、游戏战斗结算、装备数值库、现实军事模拟、自动修订历史章节、自动跨书知识共享或每章强制战斗。

作者已选择专家接入方式和双向研究范围；本文件整体及“复用故事候选确认战斗计划”的具体产品行为仍待批准。实现者可决定模块拆分、有限预算默认值及测试夹具，不得改变上述事实/确认边界。未经另行确认不commit/push/merge或重启正式服务。
