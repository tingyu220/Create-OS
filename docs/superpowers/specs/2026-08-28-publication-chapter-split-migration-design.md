# 《文明升阶》发布版拆章迁移设计

日期：2026-08-28

状态：待人工审阅

## 1. 目标

冻结已经发布的第1—4章，将当前第5—32章重编为适合连载阅读的新发布版。新章按真实戏剧节点拆分并允许轻度重写，目标为3000—4500个中文字符，5000为软上限，5500为硬上限。迁移必须保留重大 Canon 事实，重建每章生产权威链，并为旧版提供可验证、可恢复的历史归档。

本次只迁移现有内容，不续写迁移完成后的新剧情，不生成原第32章结局之后的新事件。

## 2. 已批准边界

- 第1—4章是已发布冻结区：正文、编号和内容哈希必须保持不变。
- 第5—32章是迁移源：允许拆分、相邻重组、轻度删改重复说明和补充转场/钩子。
- 不新增或删除重大世界观事实、人物关系、技术成熟度、时间顺序和事件结果。
- 旧资料先备份，禁止删除或覆盖。
- 迁移期间暂停后续新剧情生产。
- 不提交、推送或合并，除非用户另行授权。

## 3. 设计原则

### 3.1 戏剧节点优先

字符数只负责触发复核，不能决定切点。合法新章至少具有：

1. 可单独表达的章节功能；
2. 明确冲突或压力变化；
3. 人物选择、发现或不可逆行动；
4. 可验证的章节状态变化；
5. 自身章末钩子。

禁止在一句话、连续对话、单个动作或未完成因果链中间机械切割。

### 3.2 单一活动发布版

迁移完成后，新发布版是唯一活动生产序列。旧第5—32章转为历史源版，不再被下一章 Context、POV Strategy、Writer Admission 或发布出口读取。旧版并非删除，而是通过迁移清单和不可变归档继续可审计。

### 3.3 Canon 与发布编号分离

原章节编号只表示迁移来源，不再承担活动发布编号。每个新章拥有新的连续 `publication_chapter_number`，并通过来源片段列表追溯到一个或多个旧章节。平台编号与 Creative OS 活动编号必须一致，避免双重章号。

## 4. 数据模型

### 4.1 PublicationChapterMigrationManifest

迁移清单是追加式、可哈希验证的权威记录，至少包含：

- `migration_id`
- `project_id`
- `source_edition_id`
- `target_edition_id`
- `frozen_through_chapter=4`
- `source_chapter_range=5..32`
- `source_file_hashes`
- `frozen_file_hashes`
- `length_policy`
- `entries`
- `manifest_hash`
- `status`
- `approved_by`
- `approved_at`

每个 `entry` 至少包含：

- 新发布章号、标题和正文哈希；
- 有序来源片段：旧章号、段落范围、原文哈希；
- 轻度改写说明与改写后哈希；
- 章节功能、转折、结尾钩子摘要；
- Canon 保持断言；
- 对应活动合同标识和状态物化标识。

任何来源片段只能被一个最终条目消费；删除的重复内容必须进入显式 `omissions`，记录原因和原文哈希，不允许静默丢失。

### 4.2 MigrationCheckpoint

迁移采用阶段性检查点：

- `SNAPSHOT_VERIFIED`
- `PLAN_APPROVED`
- `CONTENT_REBUILT`
- `AUTHORITY_REBUILT`
- `BATCH_VERIFIED`
- `ACTIVATED`
- `FAILED`

检查点记录当前批次、输入指纹、输出指纹和错误。崩溃后只从最后一个完整检查点继续，不信任半写入目录。

### 4.3 PublicationLengthPolicy

- 目标区间：3000—4500中文字符；
- 软上限：5000，必须记录人工复核理由；
- 硬上限：5500，阻断激活；
- 低于2500：仅在短章具备独立强钩子并获人工批准时允许；
- 标题和 Markdown 标记不计入中文字符数。

## 5. 迁移流程

### 5.1 冻结与备份

1. 精确读取第1—32章和相关权威目录；
2. 记录第1—4章哈希作为冻结基线；
3. 将旧第5—32章正文及相关活动记录复制到新的只读历史版目录；
4. 对备份逐文件重算哈希；
5. 在备份验证成功前禁止写入目标版。

备份不得使用删除、移动或覆盖源文件的方式完成。

### 5.2 拆分规划

Planner 为每个旧章输出候选戏剧单元，包括场景范围、冲突、选择、结果、信息揭示、技术状态和钩子。相邻单元可重组，但必须保持原时间顺序和因果顺序。

候选规划需要人工审批后冻结。未经批准，不生成目标正文和活动合同。

### 5.3 内容重建

每个新章以已批准的戏剧单元为边界：

- 保留有效原文；
- 删除重复解释、重复证明和高潮后过长程序性尾声；
- 补充最少必要的开场承接、转场和章末钩子；
- 不使用模型自由扩写新的重大事件；
- 改写必须在清单中逐段留下来源和原因。

### 5.4 权威链重建

每个新章独立建立并验证：

1. POV Strategy 候选与人工选择；
2. schema v2 Chapter Contract；
3. Scene、Technology、SupportingAgency 和 Engagement 约束；
4. Contract Approval 与冻结版本；
5. Context、Writer Admission 与成稿指纹；
6. Reader、Narrative 和 Quality Review；
7. Fulfillment Evidence 与 Evaluator；
8. State approval、materialization 和下一章 Baseline。

拆分章节不得共用旧合同、旧 Admission Token 或旧最终状态。历史记录可作为 EvidenceRef 来源，但不能冒充当前章验证证据。

### 5.5 激活切换

只有全部目标章节完成后才允许一次性切换活动发布版。切换必须在项目级权威锁内完成：

1. 重读冻结基线和完整 Manifest；
2. 验证第1—4章哈希未变；
3. 验证新章号从5开始连续且无重复；
4. 验证每个来源片段恰好被消费或显式省略；
5. 验证每章权威链闭环；
6. 更新活动版 pointer 和接续 readiness；
7. 旧版标记为 historical，不修改其原始内容。

切换前失败不影响当前活动版；切换后恢复必须由 pointer 唯一决定活动版，不允许混读。

## 6. 模块边界

新增组件保持小而单一：

- `publication_migration_model.py`：精简领域类型与不变量；
- `publication_migration_codec.py`：canonical JSON 编解码与哈希；
- `publication_migration_store.py`：追加式 Manifest/Checkpoint 存储与恢复；
- `publication_split_planner.py`：只生成戏剧单元候选，不写正文；
- `publication_migration_service.py`：编排备份、内容重建、权威重建和激活；
- `publication_length_review.py`：长度、切点和重复尾声门禁；
- 独立 CLI：显式执行 inspect、plan、approve、rebuild、verify、activate，不提供一键绕过。

Planner 不读取网络、不调用 Writer、不持久化活动事实。迁移 Service 不复制 Narrative Director、Admission 或 State 逻辑，只调用现有权威接口。

## 7. 错误处理与恢复

- 源文件哈希漂移：阻断并重新规划受影响条目；
- 第1—4章任一哈希变化：全局阻断；
- 片段遗漏、重复消费或顺序颠倒：全局阻断；
- 新章超硬上限：阻断该章及之后的状态物化；
- Canon 漂移：人工裁决前阻断；
- 权威记录缺失或绑定旧版：阻断激活；
- 写入中断：保留已验证检查点，目标临时产物不进入活动 pointer；
- 激活中断：通过单一 pointer 和 journal 恢复到切换前或切换后完整状态，不暴露混合版本。

## 8. 验收

### 8.1 内容验收

- 第1—4章逐文件哈希与迁移前一致；
- 新章号从5连续到最终章；
- 每章目标3000—4500字，例外符合策略；
- 每章存在独立功能、转折和章末钩子；
- 无重复剧情、无原文静默丢失；
- 重大 Canon 事实、事件顺序、技术成熟度和人物关系保持；
- 原第32章结局之后没有新增剧情。

### 8.2 权威验收

- 每个新章均通过 POV、Contract、Admission、Review、Quality、Fulfillment 和 State；
- 关闭并重开全部 Store 后能够精确重建活动版；
- 旧版不能被生产 Context 或 Writer 出口读取；
- Manifest 篡改、错误哈希、重复片段、旧 token 和混合版读取均 fail-closed；
- readiness 指向迁移后最终章的下一章规划状态，但不存在该章正文。

### 8.3 工程验收

- 单元、集成、恢复和全量测试通过；
- `compileall` 通过；
- AST/出口扫描证明无旧版生产绕过；
- `git diff --check` 通过；
- 无暂存、提交、推送或合并。

## 9. 分批策略

迁移按旧章范围分批，但只在全部批次完成后激活：

1. 第5—10章：验证拆章模型、Manifest 和首批节奏；
2. 第11—18章：验证人物、技术和国际线连续性；
3. 第19—26章：验证既有场景/多 POV 返工兼容；
4. 第27—32章：验证最新权威链、超长章和最终接续基线；
5. 全书联合审计与单次活动版切换。

批次验收允许返工，但不得提前把部分新章暴露给生产入口。

## 10. 非目标

- 不修改已发布第1—4章；
- 不续写迁移后的新剧情；
- 不以固定比例轮换 POV；
- 不建立第二套 Canon 事实库；
- 不为了凑字数添加无因果价值的场景；
- 不清理既有备份或临时文件；
- 不执行 Git 提交、推送、合并或 PR。
