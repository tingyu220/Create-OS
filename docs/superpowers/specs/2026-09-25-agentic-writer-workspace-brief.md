# Agentic Writer Workspace V0.2 UI Brief

## 目标

页面的首要任务不是“显示章节文本”，而是让作者能够把一句自然语言交给 Agent，Agent 读取项目上下文后自主决定下一步创作动作，作者再审阅、修改或接受结果。

## 页面结构

```text
左侧：项目与章节导航
中间：正文编辑 / 预览 / 草稿版本
右侧：Agent 工作区
      - 当前上下文摘要
      - Agent 状态与最近动作
      - 自然语言输入
      - 提议 / 诊断 / 需要作者决定的动作
```

## 交互原则

- 用户只输入目标或问题，例如“继续写这一章”或“这一章目前写得不对，你自己检查一下”。
- 不把人物、节奏、伏笔、情绪做成强制表单；Agent 自主选择上下文和检查维度。
- Agent 的上下文来源必须可展开追溯，但技术 ID 不污染正文区。
- 写入只产生 Working Draft 或 Agent Proposal，不覆盖 Published/Canonical/Approved。
- Agent 运行中显示“读取上下文 → 形成判断 → 等待作者决定”，不伪造已完成的正文。

## 视觉方向

- 延续现有浅色、留白、弱边框语言；避免把 Agent 做成黑色聊天框或紫色 AI 面板。
- Agent 区是工作侧栏，不是页面主角；正文阅读宽度优先。
- 桌面端三栏；窄屏按“正文 → Agent → 版本”顺序堆叠。
- loading、空状态、失败、冲突和等待作者决定均有明确中文反馈。

## 本阶段实现边界

- 先接入真实 `/api/workspace` 和 `/api/agent/intents`，展示已有项目上下文摘要。
- 增加“开始续写”与“自主检查”两种意图快捷入口，但最终请求仍使用自然语言契约。
- Agent 运行结果先展示受理状态和上下文来源，不在前端伪造模型输出；后续接入真实 Agent Runtime。
- 本阶段不实现完整多轮 Agent 推理或自动发布。
