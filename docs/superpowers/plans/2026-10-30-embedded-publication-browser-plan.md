# WebView2 内嵌发布工作台实施计划

## 当前阻塞

机器已安装 WebView2 Runtime，但没有 .NET SDK；当前 8899 服务是普通 HTTP 页面，不能承载 WebView2，也不能嵌入番茄页面。

## 实施顺序

1. 增加桌面启动器工程，创建两个 WebView2 视图：Creative OS 与番茄作者后台。
2. 为每本作品建立独立用户数据目录，持久化登录态，不写入密码或 Cookie 到项目目录。
3. 建立本地桥接协议：页面 URL、登录状态、作品、章节、正文哈希、操作 ID、暂停/继续状态。
4. 将现有 `PersistentBrowserWorkbenchController` 接到桥接协议；状态未知必须先核对，禁止静默重发。
5. 只在临时作品和 Fake 页面完成逐章填充、发布、核对、暂停/继续和异常恢复验收。
6. 桌面壳验收通过后，再安排人工测试账号验证真实番茄页面字段；不自动发布真实章节。

## 不做

- 不使用 iframe 代理番茄页面。
- 不复制或保存登录凭据。
- 不在没有真实页面证据时显示“已连接”或“已发布”。
- 不改动现有 8899 网页版的普通写作流程。
